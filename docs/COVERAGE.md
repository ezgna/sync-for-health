# 取得範囲と残る制約

HealthBridge 1.1 / capture v3。これはコードが読み取る範囲の説明で、本人の端末に全項目が記録されていることや、すべての読み取りが許可されたことを示しません。

| 対象 | 保存する内容 |
| --- | --- |
| 数量・カテゴリ | SDKで利用可能な既知型。歩数、心拍、睡眠、体組成、栄養等。RMSSD、旧NikeFuel、閉経関連の新型も追加 |
| 数量の原本詳細 | 元の数量系列、各点の時刻、個数、Appleの集計値・最終計測区間 |
| 運動 | 元UUID・種類・時間・統計、一時停止/再開/ラップ、マルチスポーツの各活動区間・設定 |
| 運動の関連 | APIが返すサンプル/effortの本当の所属UUID。照会した型の範囲も記録し、時刻で関連を推測しない |
| GPS | 記録済みルートのUUID・境界・由来と、全点の緯度/経度/時刻/高度/精度/速度/方向。アプリ自体は位置追跡を開始しない |
| 心拍間隔 | 記録されたheartbeat seriesの各拍offset、gap、算出時刻。24時間の全拍が常に記録されている意味ではない |
| ECG・聴力図・心の状態 | 波形/offset、検査のmasking/clamping、raw enum等 |
| 血圧・食事 | 本来のcorrelation UUIDとmember UUID。栄養素個別値との関係を保持 |
| 質問票・視力処方 | GAD7/PHQ9の全回答・点数・risk、左右レンズと公開される処方項目 |
| 服薬 | 個別に許可された登録薬・アーカイブ状態・標準コード、dose eventの予定時刻/量と服用/スキップ等。非公開の全通知設定は含まない |
| 日別リング | 現在アクセス可能な全日の値・目標・ムーブモード・休止状態をsnapshot保存 |
| metadata | 互換文字列と型付きJSON。数値/Bool/日付/配列/辞書を区別し、未知型は未知と明示 |

服薬・視力処方は、通常のヘルスケア許可とは別に読み取る対象を選択します。アプリの設定上部からいつでも確認できます。iOSの許可画面に履歴範囲が表示される場合、全履歴を保存するには「すべての記録済みデータと今後のデータ」を選びます。

明示的な権限エラーがあれば、他項目の取得を続け、`scan_partial` と `pending_types` に残します。読み取り拒否が空結果として返る場合、記録が無い場合との区別はできません。成功表示や`scan_complete`は全データ取得の証明になりません。

## 今回追加していない範囲

- 病院連携のFHIRレコード、CDA文書、検証可能な医療記録、処方等の添付原本。追加capability・別許可・原本ファイル保存が必要で、本人のHealth内で存在を確認してから別途対応する範囲です。
- Medical ID/緊急連絡先、服薬の全リマインダー設定等、今回使用する公開HealthKit APIで提供されない情報。
- メーカーアプリにだけ保存されAppleヘルスケアへ書き込まれていない値。ベンダー固有の指標は別データ経路が必要です。

## 大きなデータと運用

大きな単独recordは元JSONを分割して送信します。受信途中の断片を保存済みsampleとは数えず、全断片のSHA256・JSON検証とSQLite COMMIT後にsampleへ反映します。単独原本最大256MiBを超える場合は、黙って省略せず停止します。端末内で巨大record全体を保持するメモリ制約は残ります。

iOSの背景実行とHealthKitのロック制限、Macの稼働、Tailscale接続が必要です。Mac停止中の未送信分は次の同期機会に再試行します。リアルタイムや定刻の取得は保証しません。

読み取るときはsource・単位・測定時刻と受信時刻を区別します。歩数等の生値を複数source間で単純合計せず、Appleの優先順位調整を再現できたとは扱いません。
